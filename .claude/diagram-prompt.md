# README 用のアーキテクチャ・フロー図を作るプロンプト

下のテンプレートの `［…］` を埋めて依頼する。このリポジトリの完成例は [図の定義](../docs/diagrams/README.md) と [描画スクリプト](../scripts/readme-diagrams.mjs)。承認された B 案「アイコン単体＋番号付き経路」を再現するためのプロンプト。

## コピーして使うテンプレート

```text
対象リポジトリ: ［パス］
プロダクトと目的: ［何をするアプリか］
読者: ［例: ポートフォリオを見るエンジニア］
作る図: ［アーキテクチャ / 技術スタック / 処理フロー］
図中の言語: ［日本語など］
参考: ［README、既存の図、承認済みの見本のパス］
出力先: ［例: docs/diagrams に定義、docs/images に SVG］

実装に基づく、アイコンと接続線で読める技術図を作ってください。
AWS の構成図のように、境界・役割・関係が一目で分かる図式を使います。
完成物はコードで組み立てた編集可能な SVG にしてください。

1. 内容を確定する
- 適用される開発ルール、README、仕様、決定記録、依存定義、実装を読む。
- 各ノードと経路が、どのコード・設定・仕様に対応するか確認する。
- 外部サービス、永続化先、実行プロセス、権限境界を実装から特定する。
- 計画段階と実装済みを区別する。存在しないクラウド、DB、API を加えない。
- 判断が必要な不明点は、対象と選択肢を具体化してまとめて確認する。
  コードで確かめられることは調査し、既に承認された方向は引き継ぐ。

2. 図ごとの問いを分ける
- アーキテクチャ: 入力から処理・保存までのデータの流れ、UI と処理の接続、
  OS・プロセス・外部通信の境界を示す。更新など補助的な通信も区別する。
- 技術スタック: 各技術の担当と利用関係を示す。実行時、ビルド、テストを
  見分けられるようにし、ロゴを並べただけの一覧にしない。
- 処理フロー: 開始・入力・処理・判断・結果を示す。判断はひし形とし、
  Yes/No など条件を経路に記載する。待機、再試行、ループの戻り先も示す。
- 一枚に詰め込みすぎない。簡略化した条件と詳細仕様への参照を添える。

3. 見た目を揃える
- 技術は実際のロゴ、機能は意味の合う統一された SVG アイコンを使う。
  既存依存を優先し、例として Simple Icons と Tabler Icons を使える。
  未使用の AWS サービスのアイコンで別の機能を代用しない。
- アイコンは単体で配置し、その下に短い名前と必要最小限の補足を置く。
  アイコンの背後にタイルやカードを敷かない。絵文字は使わない。
- 実際の責務・実行場所ごとに、細いニュートラル色の境界枠で囲む。
  グループ名を付け、カテゴリ色はアイコンや小さな境界マークに絞る。
- 背景と文字は白・グレー系を基調とし、色には一貫した役割を持たせる。
  図専用の色トークンでライト / ダークを定義する。アプリのトークンは変更しない。
- 接続線は原則として直交させる。矢印の先と向きが曖昧にならないようにする。
  線が文字・アイコンを貫通しないようにし、交差と折り返しを減らす。
- 経路に「フレーム」「IPC」「PNG を保存」のような短い意味のラベルを付ける。
  ラベル付き経路は番号を振る。番号が参照用か実行順かを明記する。
- データ、制御、テスト、任意の通信などの区別は実線・破線と凡例で示す。
  色だけに意味を依存させない。双方向矢印は実際に双方向の場合だけ使う。
- 余白、アイコンサイズ、文字サイズ、線幅を統一する。
  開始値は横幅 1440px、アイコン 56px、名前 19px、補足 15px 程度とし、
  README で縮小しても読めるかを見て調整する。
- 見出しは図の内容を表す具体的な名前にする。宣伝文、長い説明カード、
  グラデーション、影、立体表現、装飾だけのロゴは加えない。

4. 編集・再生成できる形で実装する
- ノード ID、グループ、経路、ラベル、座標を JSON などの定義に分離する。
- SVG アイコンはパスとして取り込み、自己完結した SVG を出力する。
  外部画像・外部フォント・JavaScript・foreignObject に依存させない。
- ライト / ダークを同じ構成定義から描画する。
- SVG に title / desc を付け、README の画像にも適切な説明を付ける。
- 描画スクリプト、ソース、出力ファイル、再生成コマンドをリポジトリに残す。
  必要なら互換用 PNG も書き出すが、README は SVG を参照する。
- ImageGen などの画像生成モデル、生成画像を下敷きにしたトレース、
  SVG 内へのビットマップ埋め込みは使わない。

5. 確認してから仕上げる
- 重複 ID、未定義の接続先、見つからないアイコンを検査する。
- 実際のフォントで文字を計測し、キャンバス外へのはみ出し、ラベル同士、
  文字とアイコンの重なりを検査する。
- 全図の両テーマを描画して実際に見る。自動検査に加え、矢印の到達先、
  線の交差、余白、縮小時の読みやすさも目視する。
- ノード、矢印、分岐条件をもう一度実装・仕様と照合する。
- README の参照パスとテーマの切り替え、再生成コマンドを確認する。
- プロジェクトで必要な lint・テスト・ビルドを実行し、実行結果と未確認点を伝える。

納品物: 図のソース、描画スクリプト、両テーマの SVG、README への組み込み、
再生成手順。まず既存実装から図の内容を整理し、未承認の見た目に判断が必要なら
実物の見本で確認してから完成版を作ってください。
```

## このリポジトリでの依頼例

```text
.claude/diagram-prompt.md の条件に従って README の図を更新してください。
承認済みの B 案（アイコン単体＋番号付き経路）を維持します。
対象はアーキテクチャ、技術スタック、スライド検出フローの 3 図です。
SPEC.md、DECISIONS.md、各 crate、src/ipc の実装を根拠にし、図中は日本語にします。
既存の docs/diagrams/*.json と scripts/readme-diagrams.mjs を更新し、
node scripts/readme-diagrams.mjs で両テーマを再生成してください。
```
