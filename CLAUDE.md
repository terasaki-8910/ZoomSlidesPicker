# Project: ZoomSlidesPicker

## What this is
授業の画面（Zoom のライブ、SharePoint の動画の再生など）から、先生がスライドを切り替えるたびにその画像を自動で保存し、授業の後にスライド一式（PNG と PDF）を手元に残す。Mac と Windows で動く。
Scope in SPEC.md; pass/fail criteria in ACCEPTANCE.md; decisions in DECISIONS.md (it outranks both).
Build order and status in PLAN.md.

## Workflow
No pipeline, no gated stages -- a plain conversation with Claude. Before calling a feature
done, run its tests and lint yourself (nothing runs them automatically): `sh scripts/check.sh`
runs everything.

Independent parts (crates and the frontend that don't share files) are built in parallel by
subagents, each in its own git worktree under `.worktrees/`, then reviewed (read the diff, run
the checks) and merged with `git merge --no-ff`. Implementation subagents run on Sonnet;
design, acceptance criteria, and review stay with the main session.

Until 2026-11-20 (Codex trial): the implementation in those worktrees goes to Codex CLI through
the `codex-delegate` skill instead of Sonnet subagents, while Codex quota allows. The main
session creates the worktree, writes the spec, reviews, commits, and merges.

The language I chat in is separate and unaffected.

## Commands
- Everything: `sh scripts/check.sh`
- Rust: `cargo test --workspace`, `cargo fmt --all --check`,
  `cargo clippy --workspace --all-targets -- -D warnings`;
  detection timing (ACCEPTANCE A11): `cargo test --release -p zsp-detect --test timing`
- Frontend: `pnpm test` (vitest), `pnpm lint` (eslint + no-emoji + design-tokens-only + a11y),
  `sh scripts/ui-check.sh` (Playwright + axe on the Vite build, Tauri commands mocked)
- App: `pnpm tauri dev`, `pnpm tauri build`
- Fixtures: generated by `samples/fixture/` (Python 3 with numpy and Pillow, macOS fonts):
  `.venv/bin/python samples/fixture/export_fixtures.py`. The data the Rust tests read is
  committed under `fixtures/`, so tests never need Python.
- Real-capture checks (ACCEPTANCE D): run by hand; they need a GUI session and, on macOS,
  Screen Recording permission.
