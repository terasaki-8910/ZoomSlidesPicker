# Project: ZoomSlidesPicker

## What this is
授業の画面（Zoom のライブ、SharePoint の動画の再生など）から、先生がスライドを切り替えるたびにその画像を自動で保存し、授業の後にスライド一式（PNG と PDF）を手元に残す。Mac と Windows で動く。
Scope in SPEC.md; pass/fail criteria in ACCEPTANCE.md; decisions in DECISIONS.md (it outranks both).

## Workflow
Driven by scripts/run.sh through gated stages (see pipeline.yaml). Do NOT skip gates.
`run.sh auto` is the ONE sanctioned exception: it runs intake as a conversation, then answers
every later human gate itself (repair menu = hybrid, red feature = skipped, green feature =
auto-merged locally). Machine gates still have to pass -- auto never weakens them. Do not
invoke it on my behalf; it is mine to start.
Intake proposes per-project tools (MCP/plugins/skills): Claude proposes, I approve, I
run state/init-tools.sh myself. Never auto-install or enable tools.

## Language
- SPEC.md, ACCEPTANCE.md, DECISIONS.md, design_brief.md: Japanese (DECISIONS R1-11).
- Code, comments, commit messages: English.
- UI copy: Japanese and English, chosen from the OS language and switchable in Settings
  (DECISIONS R1-10). Every UI string exists in both languages.
The language I chat in is separate and unaffected.

## Commands
Set up by the criteria stage; a half that does not exist yet is skipped by scripts/gates.sh.
- Tests: `cargo test --workspace` and `pnpm test` (vitest)
- Lint:  `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`,
  `pnpm lint` (eslint; MUST include: no-emoji, design-tokens-only, a11y)
- UI check: `sh scripts/ui-check.sh` (Playwright + axe on the Vite build, Tauri commands mocked)
- Dev: `pnpm tauri dev`
- Fixtures: generated by `samples/fixture/` (Python 3 with numpy and Pillow, macOS fonts);
  the data the Rust tests read is committed, so tests never need Python.
- Real-capture checks (ACCEPTANCE D): run by hand; they need a GUI session and, on macOS,
  Screen Recording permission. Not part of the headless gates.

## Stack recipes
If the chosen stack matches a doc under docs/recipes/ (e.g. docs/recipes/
tauri-desktop-app.md for a Tauri + pnpm desktop app), read it during intake/design and
follow its documented patterns/gotchas -- each one there cost real debugging time on a
prior project, not guessed in advance. If personal shared-infrastructure notes exist at
~/.claude/rules/infra.md (e.g. a self-hosted DB server reused across projects), check
there too -- it stays out of this repo, never committed, since this template is public.
